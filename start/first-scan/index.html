Getting started

From install to your first SBOM, step by step. The fastest path needs no command line — download the app and double-click.

Just want an SBOM or a notice quickly, no commands? Start with the no-CLI quick start.

BomLens runs on a Docker engine, but the desktop app and web UI set it up and pull the image for you. You only manage Docker yourself for the CLI — see Requirements below if you still need to install one.

Start without the command line (recommended)

Section titled “Start without the command line (recommended)”

Download BomLens for Windows (.exe) and double-click it; the UI opens with no console window. On first run it checks Docker, pulls the scanner image (about 250 MB), and opens http://localhost:8080. The app is unsigned for now, so if Windows SmartScreen warns, click More info, then Run anyway. A click-by-click walkthrough is in the no-CLI quick start.

Prefer scripts over an installer? The sbom-ui.bat alternative is covered step by step in Path B of the no-CLI quick start.

Web UI

Section titled “Web UI”

No commands beyond launching it: run in the browser, scan, and download results.

--depth 1 skips the repository history, which cuts the download from about 465 MB to about 50 MB. The first launch can take a minute or two before the page loads: the script downloads the scanner image if it is missing (about 250 MB), or checks for a newer one, and the browser tab it opens can show a connection error until the server is up. Reload the tab once the terminal prints BomLens Web UI listening.

The folder you run from is the output base: each scan saves to a {Project}_{Version}/ subfolder under it (details in Where outputs go). If the port is taken, prefix UI_PORT=9090 (bash only; on Windows, put UI_PORT=9090 in scripts\bomlens.settings.txt next to sbom-ui.bat instead; see Settings file). To scan the current folder as the source, run from that project folder (right after cloning, that is the BomLens repository itself, so for a quick first try use cd examples/nodejs && ../../scripts/scan-sbom.sh --ui instead, and the results are saved inside that folder); for a GitHub URL, ZIP, SBOM, firmware, or Docker image you supply the input in the UI, so any folder works.

  1. Enter a project name and version.
  2. Pick a scan target: current folder, GitHub URL, ZIP upload, SBOM upload, firmware upload, or Docker image.
  3. Click Run scan — logs stream live.
  4. View or download the SBOM, the notice, the risk report, and the security report.

Screen layout and per-target details are in the web UI reference.

Other inputs — a ZIP source (--target app.zip), an existing SBOM (--analyze sbom.json), firmware (--target dev.bin --firmware), a Docker image (--target nginx:latest) — are in the input-scenarios guide.

The full options are in the CLI reference; to upload the result to TRUSCA or a Dependency-Track server, use --trusca <project_id> (or UPLOAD_TARGET) — the steps are in the upload guide.

Understanding the results

Section titled “Understanding the results”

Each scan lands in a {Project}_{Version}/ subfolder, and the files inside are named {Project}_{Version}_…, for example MyApp_1.0.0/MyApp_1.0.0_bom.json:

File What it is
{Project}_{Version}_bom.json the SBOM (CycloneDX 1.6)
{Project}_{Version}_NOTICE.{txt,html} open-source notice (고지문) grouped by license
{Project}_{Version}_security.{json,md,html} Trivy vulnerability report
{Project}_{Version}_risk-report.{md,html} open-source risk report (licenses + vulnerabilities), generated by default

Requirements

Section titled “Requirements”

BomLens needs only a Docker engine — not a specific product.

Item Minimum
Docker 20.10+
Memory 4 GB+ allocated to the Docker engine
Disk 4 GB+ (for the Docker image)
OS Linux, macOS, Windows
Arch AMD64, ARM64

Every published image, including the opt-in --firmware and --deep-cve ones, supports both architectures, so pulling any of them on an ARM64 host (an Apple Silicon Mac, an Arm server) works natively; see the Docker image reference for the full list.

The memory figure is for the engine itself (the VM behind Docker Desktop, Rancher Desktop, or Colima on macOS), not the host machine. Tools like Colima default to 2 GB, which is enough for a manifest-only scan but too tight for languages where BomLens has to run an actual build to resolve transitive dependencies (Java/Gradle, Java/Maven). Under 4 GB, that build step can be killed for running out of memory, and the scan falls back to a shallower, direct-dependencies-only result. A scan that runs a Maven or Gradle build (Java, Android, or a mixed project with a pom.xml or build.gradle) on an engine with less than about 4 GB prints a warning before the build starts, with the setting to change (colima stop && colima start --memory 4 for Colima, Settings > Resources > Memory for Docker Desktop; with the WSL 2 backend, Rancher Desktop on Windows or docker-ce in WSL2, set memory=4GB in %UserProfile%\.wslconfig and run wsl --shutdown). The warning is a hint and does not stop the scan. If the dependency graph still looks thin, check the scan’s warnings for a note about it.

If you already run a Docker engine (Docker Desktop, Rancher Desktop, Colima, docker-ce in WSL2, anything), confirm it works. On macOS, Linux and WSL2 the cloned repo has a check that tests Docker, the engine, the scanner image, engine memory and the UI port in one go and says what to do about each:

If BomLens stops with Cannot reach the Docker engine, the docker command exists but the engine is not running. Start Docker Desktop or Rancher Desktop and wait for its icon to settle, or run colima start for Colima, then run the command again.

Installing Docker on macOS and Linux for the first time

Section titled “Installing Docker on macOS and Linux for the first time”
System Command or download
macOS, free and no GUI brew install colima docker, then colima start --memory 4
macOS, GUI Rancher Desktop or Docker Desktop
Linux curl -fsSL https://get.docker.com | sudo sh, then sudo usermod -aG docker "$USER" and log in again

Installing Docker on Windows for the first time

Section titled “Installing Docker on Windows for the first time”

Docker Desktop is simplest, but it needs a paid license above a certain organization size. Free options:

Option Notes
WSL2 + docker-ce (free) Install docker-ce inside WSL2 Ubuntu and run scan-sbom.sh there. No .bat, no Windows named pipe, no path-conversion issues. CLI only — does not work with the .exe installer flow above.
Rancher Desktop (free, GUI) A drop-in GUI replacement for Docker Desktop with a docker CLI. Works with the .bat double-click and desktop-app flows.
Docker Desktop Easiest, but check licensing for organizational use.

If you started with the installer (the .exe), install Rancher Desktop or Docker Desktop instead of WSL2 + docker-ce — the desktop app doesn’t yet know how to reach Docker running inside WSL2, so it will keep reporting “Docker isn’t installed” even after you set that up.
