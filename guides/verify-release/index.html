Verify a release

A tool that reports on supply chains should have a supply chain you can check. Every release is built by the project’s own GitHub Actions workflows and signed with keyless cosign (Sigstore), so you can confirm that what you downloaded was built from this repository, without trusting a key that someone could hand you.

The commands below were run against v1.13.7. Replace the version with the one you downloaded. They need cosign v2 and, for the checksum step, sha256sum (shasum -a 256 on macOS).

Release files (installers, CLI, source bundles)

Section titled “Release files (installers, CLI, source bundles)”

One signature covers the checksum file, and the checksum file covers every asset, so you verify one file and then the checksums.

Verified OK means the checksum file was signed by a workflow of the sktelecom/bomlens repository. The OK line then says your file matches the checksum in it. The desktop installers are not code-signed yet (the first run shows a SmartScreen or Gatekeeper warning, see first scan); this check is how you confirm one is the project’s build.

On Windows

Section titled “On Windows”

You need no gh, sha256sum or jq for this check. Download cosign-windows-amd64 from the cosign releases page into the folder you work in, rename it to cosign.exe, then run this in PowerShell. It downloads the installer and its checksum files, verifies the signature on the checksum file, and compares the installer’s hash with the one listed.

If the last line prints MISMATCH, do not run the installer.

Container image

Section titled “Container image”

The project’s own SBOM

Section titled “The project’s own SBOM”

Each release also attaches bomlens-source-<version>.cdx.json, the SBOM of every manifest the repository ships (the desktop app’s and the web UI’s dependencies). It is covered by the same checksum file.

What this does not tell you

Section titled “What this does not tell you”

A valid signature says who built the file, not that the code is free of defects. The scanner image is scanned by Trivy every night and the findings are public in the repository’s Security tab, and the limitations page lists what the tool does not do.
