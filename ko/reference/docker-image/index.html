Docker 이미지 직접 사용

평소에는 scan-sbom.sh 스크립트 사용을 권장합니다. 스크립트가 언어 감지와 이미지 선택, 볼륨 마운트를 대신 처리하기 때문입니다. 이 문서는 스크립트를 둘 수 없는 환경(CI 러너, 쿠버네티스 잡 등)에서 이미지를 docker run으로 직접 호출하는 방법을 설명합니다.

이미지와 태그

Section titled “이미지와 태그”
이미지 용도
ghcr.io/sktelecom/bomlens 스캔과 후처리 (대표 이름)
ghcr.io/sktelecom/sbom-generator, ghcr.io/sktelecom/sbom-scanner 같은 이미지의 별칭 (이전 이름, 같은 다이제스트)
ghcr.io/sktelecom/bomlens-firmware 펌웨어 분석용 (GPL 도구 포함, opt-in) (legacy alias: sbom-scanner-firmware)
ghcr.io/sktelecom/bomlens-deep-cve 심층 CVE 매칭용 grype 포함 (opt-in). CLI의 --deep-cve와 웹 UI의 심층 CVE 매칭 토글이 쓰며, 둘 다 지금 실행 중인 이미지가 이 이미지가 아니면 곁들임 컨테이너로 자동으로 내려받습니다
ghcr.io/sktelecom/bomlens-deep-license 프로젝트 자체 파일의 라이선스 탐지용 scancode 포함 (opt-in). 소스 스캔에서 CLI의 --deep-license가 쓰며, 자동으로 내려받습니다. LGPL 구성요소(linux/amd64의 7-Zip, intbitset, chardet)가 들어 있습니다. 7-Zip과 intbitset의 소스는 이미지 안 /usr/share/bomlens/sources/에 있고, chardet은 파이썬 소스 형태로 들어 있습니다
ghcr.io/sktelecom/bomlens-aibom AI 모델 ML-BOM 생성용 (opt-in, legacy alias: sbom-scanner-aibom). --model/--model-file과 웹 UI의 AI 모델 타일이 쓰며, 곁들임 컨테이너로 자동으로 내려받습니다

latest와 버전 태그를 제공합니다. 발행되는 모든 이미지(ghcr.io/sktelecom/bomlens, bomlens-firmware, bomlens-deep-cve, bomlens-deep-license, bomlens-aibom 및 별칭)가 linux/amd64와 linux/arm64를 모두 지원하므로, arm64 호스트(Apple Silicon 맥, Arm 서버)에서도 그대로 pull해 쓸 수 있습니다. 이미지는 cosign으로 서명되어 발행됩니다.

arm64 호스트에서는 linux/amd64를 강제하지 마세요(--platform linux/amd64나 DOCKER_DEFAULT_PLATFORM=linux/amd64). 그러면 이미지가 에뮬레이션으로 돌고, 펌웨어 이미지 안의 syft가 비정상 종료할 수 있습니다. 펌웨어 스캔은 실패한 syft 실행을 한 번 더 시도하고(시간 제한을 넘겼거나 메모리 부족으로 강제 종료된 실행은 다시 시도하지 않음), 에뮬레이션으로 돌고 있다는 사실을 로그에 남깁니다. 두 번째 시도도 실패하면 bomlens-result.json에 generate를 degraded로 기록합니다.

이미지에 들어 있는 것

Section titled “이미지에 들어 있는 것”

언어 toolchain이 없는 경량 이미지(python 3.12 slim 기반)입니다. 소스 스캔의 전이 의존성 해석은 스크립트가 cdxgen 언어별 이미지를 따로 받아 처리합니다. 구조는 아키텍처를 참고하세요.

도구 버전 역할
syft v1.54.1 이미지, 바이너리, 디렉터리 스캔
Trivy v0.75.0 취약점 보고서
cosign v3.1.3 SBOM 서명
jq — SBOM 정규화와 고지문 생성
ScanCode Toolkit 32.5.0 정밀 라이선스 탐지 (opt-in 빌드에만 포함)
SCANOSS 1.54.2 C/C++ 소스에 복사해 넣은 오픈소스 식별(--identify-vendored)
docker CLI 29.9.0 웹 UI가 소스 스캔에서 cdxgen 컨테이너를 sibling으로 띄울 때 사용
cdxgen 13.5.0 모델 계보 정보 보강(bomlens-aibom 이미지 전용)

도구 버전은 docker/Dockerfile의 ARG로 고정됩니다.

모든 이미지에는 NVD CPE 인덱스(cpe_match.sqlite, 약 146 MB)도 들어 있으며, 이미지를 빌드할 때 NVD 데이터로 만듭니다. 펌웨어, 루트 파일시스템, 바이너리 스캔에서 --security를 켜면 패키지 PURL이 없는 컴포넌트의 CPE를 네트워크 없이 이 인덱스와 대조합니다(CVE 대조 방식 참고). 인덱스를 만들 때 GitHub에서 NVD 데이터 피드를 복제합니다. GitHub에 접속할 수 없는 환경에서 이미지를 직접 빌드하면 빌드가 이 단계에서 멈추고 --build-arg SBOM_CPE_INDEX=false를 안내하며, 이 옵션으로 인덱스를 뺄 수 있습니다. 펌웨어 빌드는 이 옵션을 받지 않으므로 펌웨어 이미지에는 항상 인덱스가 들어갑니다.

Docker 이미지 분석

Section titled “Docker 이미지 분석”

Windows Git Bash에서는 MSYS가 /var/run/docker.sock과 컨테이너 쪽 경로인 /host-output을 둘 다 Docker에 넘기기 전에 자기 마음대로 Windows 경로로 바꿔버려서 두 마운트가 조용히 깨집니다. 아래 MSYS_NO_PATHCONV와 MSYS2_ARG_CONV_EXCL은 그 변환을 끄고, cygpath -m으로 호스트 쪽 경로만 직접 변환합니다(scripts/scan-sbom.sh도 같은 이유로 같은 조합을 씁니다). WSL2·macOS·Linux 셸은 경로를 바꾸지 않으므로 그냥 평범한 docker run 줄로 바로 넘어갑니다.

소스 디렉터리 분석

Section titled “소스 디렉터리 분석”

직접 실행의 SOURCE 모드는 트리 전체를 덮는 lock 파일(package-lock.json, npm-shrinkwrap.json, pnpm-lock.yaml, bun.lock, gradle.lockfile 중 하나이고 루트 아래 다른 매니페스트가 없을 때)을 빌드도 Docker 소켓도 없이 그대로 읽고, 빠진 라이선스는 패키지 레지스트리에서 채웁니다. SBOM에는 이 방식이 bomlens:detection으로 남습니다. 사이드 컨테이너를 띄울 Docker가 없는 환경, 예를 들어 이 이미지를 작업 이미지로 쓰는 CI 작업에서 쓰는 형태입니다. 그 밖의 트리는 컨테이너 안에서 syft가 패키지 매니페스트를 읽는 방식이라 직접 의존성만 잡힐 수 있습니다. 전이 의존성까지 필요하면 cdxgen 언어 이미지를 라우팅하는 scan-sbom.sh를 쓰세요. syft의 매니페스트 판독기는 의존성을 하나라도 풀어내려면 락파일(Node는 package-lock.json, npm-shrinkwrap.json, yarn.lock, pnpm-lock.yaml, 다른 생태계도 마찬가지)이 있어야 합니다. 락파일이 없으면 직접 실행의 SOURCE 모드는 읽을 것이 없어, 빈 결과를 완료로 보고하는 대신 안내와 함께 실패합니다.

환경 변수

Section titled “환경 변수”
환경 변수 필수 기본값 설명
MODE X POSTPROCESS 분석 모드: SOURCE, IMAGE, BINARY, ROOTFS, FIRMWARE, ANALYZE, 또는 PLAN(소스 스캔의 실행 계획 작성, 엔진 계약 참조). 지정하지 않으면 출력 디렉터리에 이미 있는 SBOM을 후처리만 한다 — 실제로 무언가를 스캔하려면 명시적으로 지정해야 한다.
PROJECT_NAME O — 프로젝트 이름
PROJECT_VERSION O — 프로젝트 버전
TARGET_IMAGE 모드별 — IMAGE 모드의 이미지. docker.sock을 마운트하면 Docker 데몬에서 읽고, 마운트하지 않으면 레지스트리에서 읽거나 형식 접두사가 붙은 아카이브(docker-archive:, oci-archive:, oci-dir:, 컨테이너에 마운트한 경로)에서 읽음
SYFT_REGISTRY_AUTH_USERNAME, SYFT_REGISTRY_AUTH_PASSWORD, SYFT_REGISTRY_AUTH_TOKEN, SYFT_REGISTRY_AUTH_AUTHORITY — — IMAGE 모드: 비공개 레지스트리의 자격 증명. docker 설정 파일을 마운트하고 DOCKER_CONFIG로 지정해도 됨. SYFT_REGISTRY_INSECURE_SKIP_TLS_VERIFY와 SYFT_REGISTRY_INSECURE_USE_HTTP는 자체 서명 인증서나 HTTP 레지스트리에 접속할 때 씀. SYFT_PLATFORM은 여러 플랫폼 이미지에서 플랫폼을 고름
TARGET_FILE 모드별 — BINARY/FIRMWARE 모드의 파일 경로 (컨테이너 내부 경로)
TARGET_DIR 모드별 — ROOTFS 모드의 디렉터리 경로
UPLOAD_ENABLED — true false면 업로드 없이 로컬 저장만 (CLI --generate-only와 동일)
HOST_OUTPUT_DIR — — 산출물을 복사할 마운트 경로
BOMLENS_STAGE1_EXIT, BOMLENS_STAGE1_OOM, BOMLENS_STAGE1_LOG, BOMLENS_STAGE1_REASON — — 1단계를 직접 실행한 뒤의 POSTPROCESS: 그 종료 코드, 메모리 부족으로 종료됐으면 true, 출력 폴더에 둔 로그 파일 이름. 뒤의 두 값 대신 이미 분류한 사유(oom, disk-space, network, cdxgen-crash, cdxgen-unavailable)를 넘겨도 됨. 종료 코드 127은 cdxgen-unavailable로 읽으므로, 1단계를 실행하지 않는 unsupported 계획에서는 이 값을 넘김. 1단계가 SBOM을 남기지 않았으면 2단계가 syft 스캔으로 대신함(엔진 계약 참조)
BOMLENS_EVENTS — — file 또는 stderr: 진행 이벤트를 한 줄에 JSON 객체 하나씩 출력 폴더의 bomlens-events.jsonl 또는 표준 오류에 씀(엔진 계약 참조)
BOMLENS_IMAGE_REF, BOMLENS_IMAGE_DIGEST — — 호출자가 실행한 이미지 참조와 다이제스트. bomlens-result.json에 그대로 적습니다(엔진 계약 참고)
GENERATE_NOTICE — false 오픈소스 고지문 생성 (CLI --notice)
GENERATE_SECURITY — false Trivy 보안 보고서 생성 (CLI --security)
DEEP_LICENSE — false scancode로 프로젝트 자체 파일의 라이선스 탐지 (CLI --deep-license, 이미지에 scancode 필요)
DEEP_LICENSE_MAX_FILES — 20000 DEEP_LICENSE: 프로젝트 자체 파일이 이보다 많은 트리는 검사하지 않음
DEEP_LICENSE_TIMEOUT — 600 DEEP_LICENSE: scancode를 멈출 때까지의 초
BOMLENS_DEEP_LICENSE_ALL — — DEEP_LICENSE: 1이면 의존성, 빌드, 도구 폴더까지 검사 (기본은 제외)
DETECTION — auto SOURCE 모드 전용. auto는 트리를 덮는 lock 파일이 있으면 정적으로 읽고 그 외에는 예전처럼 빌드나 syft 경로를 쓴다. static은 항상 정적으로 읽고, build는 정적으로 읽지 않는다(CLI --detection). 정적 검출은 빠진 라이선스를 패키지 레지스트리에서 채우므로 BYTE_STABLE=true나 FETCH_LICENSE=false에서는 auto가 빌드한다
REACHABILITY — false 각 Go 보안 권고의 코드에 도달하는지 govulncheck로 판정 (CLI --reachability). BINARY 모드는 실행 파일을 읽고, SOURCE와 POSTPROCESS는 1단계가 남긴 govulncheck 출력을 읽는다(CLI가 이미지의 govulncheck를 1단계에 넘긴다)
GENERATE_REPORT — false 오픈소스 위험 보고서 생성 (CLI 기본값과 달리 직접 실행은 꺼짐)
ENRICH_MAVEN_CPE — true maven 컴포넌트에 groupId로 유도한 NVD 매칭용 cpe:2.3을 부여해 CPE 기반 엔진이 NVD 전용 CVE를 찾게 함. 매핑 불가한 group은 CPE를 붙이지 않음 (AI SBOM은 건너뜀)
ENRICH_GITHUB_CPE — true 소수의 손검증된 pkg:github/ 컴포넌트(패키지 매니저 생태계가 없는 대형 C/C++ 프로젝트에 흔한, 소스 저장소 좌표로만 식별되는 컴포넌트)에 NVD 매칭용 cpe:2.3을 부여해 CPE 기반 엔진이 NVD 전용 CVE를 찾게 함. 큐레이션 목록에 없으면 CPE를 붙이지 않음 (AI SBOM은 건너뜀)
ENRICH_UPSTREAM_PURL — true 펌웨어, 루트 파일시스템, 바이너리 스캔과 Yocto 빌드의 기록에서 읽은 SBOM에서 purl이 없거나 pkg:generic, pkg:opkg purl인 컴포넌트에 upstream 소스 저장소 purl(pkg:github/<owner>/<repo>@<tag>, pkg:sourceforge, pkg:gnu)을 붙임. docker/lib/upstream-purl-map.json의 변환표에 있는 프로젝트와, 소스 내려받기 주소가 GitHub이나 GNU 릴리스를 밝히는 컴포넌트만 바꾸고, 나머지는 원래 식별자를 둠
ENRICH_INTERPRETER_CPE — true 소수의 손검증된 인터프리터 컴포넌트(예: conda나 NuGet 패키지로 배포된 Python)에 NVD 매칭용 cpe:2.3을 부여해 CPE 기반 엔진이 NVD 전용 CVE를 찾게 함. 큐레이션 목록에 없으면 CPE를 붙이지 않음 (AI SBOM은 건너뜀)
SECURITY_NVD_VERIFY — false --deep-cve 사용 시: grype nvd:cpe 결과를 실시간 NVD 버전 범위로 검증해 범위 밖 오탐을 제거 (NVD_API_KEY·네트워크 필요, 수 분 추가). 기본 off — 결과는 유지하되 버전 미검증으로 표시
NVD_API_KEY SECURITY_NVD_VERIFY에 필요 — deep-cve 버전 필터가 쓰는 NVD API 키. 컨테이너에 이름으로만 전달(값은 인라인하지 않음)

BOMLENS_TRIVY_DB_MAX_AGE_DAYS — 7 /trivy-db에 Trivy 데이터베이스를 마운트했을 때(갱신 없이 오프라인으로 읽음), 보안 단계를 열화로 기록하는 경과 일수
BOMLENS_GRYPE_DB_MAX_AGE_DAYS — 7 --deep-cve 사용 시 grype 데이터베이스를 대조 전에 grype db update로 갱신하는 기준 경과 일수. 이미지의 캐시에 쓸 수 없으면 임시 폴더에 받고, TRIVY_OFFLINE_SCAN이나 TRIVY_SKIP_DB_UPDATE가 true이면 갱신하지 않는다. 갱신하지 못한 데이터베이스도 그대로 읽고, deep-cve 단계를 경과 일수와 함께 degraded로 기록한다. 갱신한 데이터베이스는 컨테이너가 끝나면 사라지므로, 이미지의 데이터베이스가 오래된 동안에는 스캔할 때마다 다시 내려받는다. /trivy-db에 Trivy 데이터베이스를 마운트하면 오프라인 스캔이 되어 grype도 갱신하지 않는다
GRYPE_DB_UPDATE_URL — grype 기본값 --deep-cve 사용 시 grype db update가 grype 데이터베이스를 받는 주소. 미러를 쓸 때 지정한다

BOMLENS_GO_VULNDB_MAX_AGE_DAYS — 7 Go 취약점 데이터베이스를 오래된 것으로 보는 경과 일수. 데이터베이스 자체의 날짜(index/db.json)부터 셈. 이미지에 든 스냅숏이 오래됐으면 그 스캔에서는 임시 폴더에 내려받은 데이터베이스(약 3.6 MB, 제한 60초)를 대신 읽고, 스캔이 끝나면 지움. 오프라인 스캔이거나(TRIVY_OFFLINE_SCAN 또는 TRIVY_SKIP_DB_UPDATE가 true, /trivy-db 마운트일 때처럼) 내려받기에 실패하면 오래된 스냅숏을 읽고 go-vulndb 단계를 열화로 기록
BOMLENS_GO_VULNDB_URL — https://vuln.go.dev/vulndb.zip 그 내려받기의 주소. vulndb.zip의 미러를 지정(http, https, file URL). 읽기 전에 이미지 빌드 때와 같은 방법으로 검사
BOMLENS_EXTRA_CA_CERTS - - TLS를 검사하는 프록시를 쓸 때 신뢰할 CA 번들(PEM)의 컨테이너 안 경로. 이미지를 직접 실행할 때는 번들을 마운트하고(읽기 전용이면 충분) 이 변수에 그 경로를 지정. 엔트리포인트가 시스템 번들의 사본(SSL_CERT_FILE, REQUESTS_CA_BUNDLE, CURL_CA_BUNDLE, CARGO_HTTP_CAINFO, GIT_SSL_CAINFO, PIP_CERT), NODE_EXTRA_CA_CERTS, JAVA_TOOL_OPTIONS로 지정한 JDK 트러스트 스토어 사본에 추가한다. 이 파일들은 /tmp 아래에만 쓰므로 /tmp만 쓸 수 있으면 루트 파일 시스템이 읽기 전용이어도 된다. 읽을 수 없거나 PEM 인증서가 없는 경로면 [WARN]을 출력하고 추가 CA 없이 계속 진행. ENRICH_OS_CONTEXT — true 배포판 패키지 PURL(rpm·deb·apk)에서 operating-system 컴포넌트를 합성. Trivy가 이 컴포넌트를 보고 배포판 취약점 피드를 고르므로, 없으면 공급사 SBOM이나 rootfs 스캔의 OS 패키지는 OS CVE 매칭이 전혀 안 됨. 인식 가능한 배포판 패키지가 없으면 아무 동작도 하지 않음. Trivy가 피드를 제공하지 않는 배포판(예: OpenWRT)도 대상에서 제외 (AI SBOM은 건너뜀)

STALENESS_ENRICH — false deps.dev 버전 최신성(최신 대비 몇 릴리스 뒤처졌는지) 추가. 네트워크 접근 필요
ENRICH_HF_SECURITY — true AIBOM 모드에서 HuggingFace의 파일별 보안 스캔 결과(ClamAV·picklescan)를 ML-BOM에 기록. 메타데이터만 읽고 파일은 내려받지 않음
